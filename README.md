# Pocket-sized True Random Number Generator using weak radioactive source
Pocket-sized True Random Number Generator leverages radiation decay measured by a Geiger counter to produce high-quality entropy. The device processes these random physical events into cryptographically useful bitstreams directly on an RP2040 microcontroller - Raspberry Pi Pico H.

### Repository content

* `/models`: 3d-models used for printing devices case and double walled box for the radioactive isotope.

* `/code`: Full CircutPython code used in the device.

* `/sp800_22_tests`: implementation of the NIST SP800-22 Rev1a tests suite in python created by [dj-on-github](https://github.com/dj-on-github).

* `/data`: Samples of the random sequences generated by the device.

### Hardware configuration

* **Output**: Random data is piped securely to a host device over a USB CDC data connection.

* **Geiger Counter Interface**: Uses the RP2040's Programmable I/O (PIO) on pin GP0. A dedicated state machine runs at 100 MHz to measure the clock cycles between incoming radiation pulses. Device detects background radiation or radioactive isotope by Gravity Geiger Counter SEN0463 but any other detector that lowers the voltage on event detection will work.

* **Real-Time Clock and Local Storage**: An integrated Adafruit PiCowbell Adalogger with PCF8523 RTC module and SD slot communicates 
* * via I2C - pins GP4 and GP5 to timestamp logs and provide nonce to DRBG 
* * via GP16, GP17, GP18, GP19 to allow headless data collection.

### Entropy extraction & calibration

* **Von Neumann Debiasing**: An optional software flag applies a Von Neumann extractor to the raw interval bits, eliminating bias in older bits of the counter.

* **SD Logging**: The system can write raw cycle data and interval timestamps to a SD card for offline randomness collection.

* **TRNG**: Device can send generated bytes via USB port to be used as an entropy source to the operating system or to be gathered in a file.

### Cryptography & self-testing

* **Hash DRBG**: The device can optionally feed a built-in Deterministic Random Bit Generator. It gathers 55 bytes of pure entropy to seed the generator, outputting data in 1024-byte chunks.

* **Embedded Statistical Tests**: Implements on-the-fly health checks using Monobit, Frequency within Block, Runs, Longest Run, Serial, Approximate Entropy, and Cumulative Sums tests from NIST SP800-22 Rev1a test suite.

## Reading random bytes on Linux
Since the `boot.py` file enables both the console and the data channel (`usb_cdc.enable(console=True, data=True)`), the microcontroller will expose two separate serial ports when connected.

### 1. Identify the data port

After plugging in the device, open your terminal and list the connected serial devices:

```bash
ls -l /dev/ttyACM*
```

You will typically see two devices listed:

`/dev/ttyACM0` – The REPL console

`/dev/ttyACM1` – The data channel

### 2. Configure permissions and add packages

- Add your user to the dialout group. You must log out and log back in (or restart your computer) for this change to take effect.
```Bash
sudo usermod -aG dialout $USER
```
- Script below uses `serial` package. You can install it by running:
```bash
pip install pyserial
```

### 3. Read and print the data

Create a script with the following code to listen to the data channel and print the received bytes.
```py
Python

import serial

PORT = '/dev/ttyACM1' 
BAUDRATE = 115200 

try:
    with serial.Serial(PORT, BAUDRATE, timeout=1) as ser:
        print(f"Opened port {PORT}. Waiting for entropy from the Geiger counter...")
        
        while True:
            byte_data = ser.read(1)
            
            if byte_data:
                hex_val = byte_data.hex()
                int_val = int.from_bytes(byte_data, byteorder='big')
                print(f"Received byte: 0x{hex_val} (Dec: {int_val})")
                
except serial.SerialException as e:
    print(f"Serial port error: {e}")
except KeyboardInterrupt:
    print("\nStopped listening.")
```

### 4. Save the data
You can run the attached script using default settings to immediately start saving raw binary data to your working directory:

```bash
python read_bytes.py
```

**Command-Line Arguments**

| Argument | Short Flag | Description | Default Value |
| --- | --- | --- | --- |
| `--port` | `-p` | Defines the serial port the Geiger counter is connected to. | `/dev/ttyACM1`<br> |
| `--baudrate` | `-b` | Sets the serial baud rate. | `115200`<br> |
| `--output` | `-o` | Specifies the destination file path for the saved data. | `random_bytes.bin`<br> |
| `--format` | `-f` | Determines how the bytes are encoded in the output file. | `bin`<br> |
| `--verbose` | `-v` | Prints the hex and decimal values of each gathered byte to the console. | Disabled |

**Supported Output Formats (`-f`)**

* **`bin`**: Writes the raw binary byte stream to the file.
* **`hex`**: Converts the bytes into hexadecimal digits, outputting them at 32 bytes per line.
* **`asci`**: Maps the random bytes to printable ASCII characters (`chr(32 + (b % 95)`), saving 32 characters per line.
* **`dec`**: Outputs space-separated decimal numbers, formatting them with 16 values per line.
* **`bits`**: Saves the data as literal binary strings (0s and 1s), writing 8 bytes per line.

**Stopping the Capture**
The script will wait and listen for data indefinitely. Press `Ctrl+C` in your terminal to stop the process. The script will automatically flush any remaining buffered text data to your output file before exiting.

### 5. Test the randomness
 To perform full analysis on generated sequence run:
```bash
./sp800_22_tests/sp800_22_tests.py ./data/random_bytes.bin
```

## Feeding TRNG entropy to the Linux kernel
You can feed randomness directly into the Linux kernel to improve system cryptography using either a Python script or the standard Linux `rng-tools` daemon.

### Method 1: Python script

To increase the kernel's entropy pool, data must be injected using the `RNDADDENTROPY` system call. The following script batches the bytes from the serial port and injects them into `/dev/random`.

**Prerequisites:** You must run this script with `sudo` or as root.

```python
import serial
import fcntl
import struct

PORT = '/dev/ttyACM1' 
BAUDRATE = 115200 

# The ioctl code for RNDADDENTROPY on x86, x86_64, and ARM Linux
RNDADDENTROPY = 0x40085203 

try:
    dev_random = open('/dev/random', 'wb')
except PermissionError:
    print("Error: You must run this script as root to inject entropy.")
    exit(1)

try:
    with serial.Serial(PORT, BAUDRATE, timeout=1) as ser:
        print(f"Opened port {PORT}. Gathering entropy from Geiger counter...")
        
        buffer = b''
        chunk_size = 32
        while True:
            byte_data = ser.read(1)
            if byte_data:
                buffer += byte_data
                if len(buffer) >= chunk_size:
                    entropy_bits = len(buffer) * 8
                    buf_size = len(buffer)
                    fmt = f'ii{buf_size}s'
                    payload = struct.pack(fmt, entropy_bits, buf_size, buffer)
                    fcntl.ioctl(dev_random, RNDADDENTROPY, payload)
                    print(f"Injected {buf_size} bytes ({entropy_bits} bits of entropy) into the kernel.")
                    buffer = b''
                
except serial.SerialException as e:
    print(f"Serial port error: {e}")
except KeyboardInterrupt:
    print("\nStopped listening.")
finally:
    dev_random.close()
```

### Method 2: Using rngd

For long-term or production use, the standard Linux rngd (from rng-tools) is recommended. It runs continuously in the background and constantly performs FIPS 140-2 cryptographic tests on the incoming data stream to ensure the sensor hasn't failed or become biased.

#### 1. Install rng-tools:
```Bash

# Debian/Ubuntu
sudo apt install rng-tools

# RHEL/Fedora
sudo dnf install rng-tools
```
#### 2. Configure the serial port:
Set the correct baud rate and tell Linux not to parse the raw binary data for terminal control characters.

```Bash
sudo stty -F /dev/ttyACM1 115200 raw -echo
```
3. Run the Daemon:
Tell rngd to use the serial port as the hardware RNG source.
```Bash
sudo rngd -r /dev/ttyACM1 -f -v
```
(Omit the -f and -v flags to let it run silently in the background as a standard daemon).
